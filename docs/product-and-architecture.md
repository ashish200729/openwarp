# Product scope and architecture

OpenWarp is an independent, single-company deployment for administrators who manage employee records and colleagues who need a readable work directory. The landing page uses a pixel-grid visual system derived from the supplied references. The product uses the same colors, marks and meters with denser layouts for day-to-day work. The public charts and directory preview are labeled sample data.

## Data and access

- Better Auth owns password hashing and database sessions. Operators provision accounts separately from employee profiles. Viewers see active employees, teams and reporting links that are visible to their role. Only administrators can view other employee statuses, open and complete checklists, change records, export data, or see the activity log. Server entry points verify access, and writes recheck the role in their transaction. [Next.js authentication guide](https://nextjs.org/docs/app/guides/authentication), [Better Auth PostgreSQL adapter](https://better-auth.com/docs/adapters/postgresql)
- PostgreSQL enforces case-insensitive team name uniqueness, normalized unique employee emails, foreign keys, valid dates, and at most one open checklist per employee. A short transaction lock serializes administrative writes, including reporting checks and role changes. Version checks stop stale profile and team forms from silently overwriting new changes. The runtime role can append activity and has no grant to rewrite or delete it. Database operators retain administrative access. [PostgreSQL constraints](https://www.postgresql.org/docs/17/ddl-constraints.html), [locking](https://www.postgresql.org/docs/17/explicit-locking.html)
- Adding someone can start onboarding or create an active profile. Onboarding completion activates the employee. Cancelling onboarding archives the profile. Starting offboarding requires a last day. Completing offboarding requires every task and reassignment of direct reports. Cancelling offboarding returns the employee to active status. Archived profiles retain their history and can start a new onboarding checklist for a rehire.
- New checklists copy the task template into durable rows. Checklist actions track human work outside OpenWarp. No third-party action runs when a task is completed. Primary employee edits, workflow changes and their history entries commit together.
- Next.js Server Components render private pages from the server. Client JavaScript handles form pending states, account actions and active navigation. Employees can browse the directory as responsive cards or a wider table. Color is paired with labels, and data meters have names and numeric values. [WCAG reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow)
